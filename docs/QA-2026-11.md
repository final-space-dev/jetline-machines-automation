# Quality loop, November 2026

The loop Alwyn asked for on 10 November 2026: capture every screen in every
state, look at each picture, list what is wrong, fix it, capture again, until
two passes in a row find nothing. This file is the record. Screenshots hold
real store data and stay out of git.

## How a pass is run

- **Where**: the deployed dev address, https://jetline-machines-dev.vercel.app,
  signed in with the dev-only accounts, past Vercel's sign-in with the dev
  project's bypass token (`docs/DEV-ENVIRONMENT.md`).
- **Who**: an admin (`dev-admin`), the least-privileged kinds the system has:
  store staff (`dev-store`, Alberton) and a custom-access user with one menu
  item granted (`dev-custom`, Machine reports only).
- **Widths**: 1280, 834 and 390 px.
- **States**: every route; every tab of every tabbed screen (a store's three,
  fleet health's four, machine reports' six, Config's nine); every dialog and
  confirm; forms with their errors showing; open lists and calendars; bulk
  actions on equipment up to the confirm; the import up to (not including)
  the write; empty searches; not-found pages; what a refused person sees.
- **Recorded for every state**: console errors, page errors, every request
  that answers 4xx or 5xx (except the one a state exists to show), a page
  wider than its screen, tap targets under 44 px on the phone, axe
  (wcag2a, wcag2aa, wcag21a, wcag21aa), and for dialogs whether Tab stays
  inside and Escape closes. All of it goes to files that are read whole.
- The walk script is not in git (it holds nothing secret, but it clicks
  through dev data); it lives with the screenshots.

### Logic bugs found, fixed on dev with a test

These were in the code before the UI work and production has them.

1. **Printer volume history never drew.** Readings arrive from Postgres as
   strings; the page only accepted numbers, so every month's volume was 0.
   `src/lib/numbers.ts`, `tests/unit/lib/numbers.test.ts`.
2. **Escape left the page from inside a dialog.** The item and printer pages
   bind Escape to "back to the store". With a confirm, a list or a calendar
   open, Escape closed it and also left the page, losing unsaved edits. The
   shortcut now waits while an overlay is open. `src/lib/use-hotkey.ts`,
   `tests/unit/lib/use-hotkey.test.ts`.
3. **Machines needing attention were counted once per warning**, so the
   figure could exceed the number of machines. Each machine now counts once.
   `src/lib/machine-mapping.ts`, `tests/unit/lib/machine-mapping.test.ts`.
4. **A custom-access user got a 500 from the bell and the activity count on
   every page.** The "no store" value those two routes pass to the database
   began with a NUL character, which Postgres refuses. It is plain text now.
   `src/lib/store-scope.ts`, `tests/unit/lib/store-scope.test.ts`.
5. **Store analysis** (before the pass): machines with no readings are left
   out of the utilisation bands. `src/lib/utilization-summary.ts` and its test.

### Logic bugs found, fixed on dev with a test

6. **A machine with two Xerox records was judged once per record.** Xerox
   holds 49 of the 333 serials twice (the printer and its print server, or an
   old record beside a new one). The Operations alert feed grouped by record,
   so the stale record raised a Critical alert for a machine whose other
   record had read yesterday, while Reading health on the same screen (which
   groups by serial) said none were critical. A machine is now judged by its
   newest reading across its records, and a store's printer list shows each
   machine once. `src/lib/reading-alerts.ts`,
   `tests/unit/lib/reading-alerts.test.ts`. Production has the same fault.
